# 00 — 总体架构：一条工作流、五个模块、七个共享服务 + 三个专用服务

> 本文件回答三个问题：**为什么现在做、做成什么样、靠什么拼起来。**
>
> **展业范围（本版）**：**香港 + 新加坡**。内地不作为销售/招揽市场；涉及中国税务居民的跨境税务、CRS、21 号公告与数据出境，仍按客户税务居民身份处理（不等于"内地展业"）。
>
> **本设计在整体核心系统中的位置**：本蓝图覆盖的是 **HSBC Private Bank 核心系统中"超越 Avaloq 既有标准能力"的部分**——即 Avaloq 尚未提供的五个用例（提案→订单、量化实验室、RM 副驾、创始人全景、税务优化）。Avaloq 标准功能将按同一套数据模型、权限矩阵与证据底座**逐步纳入**，届时本蓝图是核心系统的组成部分而非替代品。因此本文件以"**HSBC Private Bank 核心系统蓝图**"命名，而不以某一个用例组命名。

## 1. 为什么现在做：五个已经发生的变化

| 变化 | 事实锚点 | 对私行的含义 |
|---|---|---|
| **亚洲成为主战场，但增长从"贝塔"转向"份额"** | 汇丰亚洲私行 AUM 约 3,020 亿美元、亚洲第二（二手口径，引用前需核对原始榜单），亚洲占其全球私行 AUM 的 53.4%；2025 年财富费用及其他收入 +24% 至 94 亿美元，净新增投资资产 800 亿美元，64 个财富中心（年内新开 27 个） | 增量还在，但"躺着涨"结束；效率与单客钱包份额决定胜负 |
| **客户要"确定"，不要"超额"** | 60.8% 把本金波动容忍度压在 10% 以内；78.1% 过去一年实际收益落在 0–10%（中国银行 2026 白皮书调研） | 提案的第一目标不是收益最大化，而是"结果可解释、下行可承受" |
| **跨境与传承是两条确定的增量** | 香港 2025 年跨境财富 2.9 万亿美元、全球第一；私行 AUM 12.9 万亿港元、+24%；单一家办超 3,380 家；家族信托余额 2024 年末 6,435.79 亿元 → 2025Q3 9,500 亿元以上 | 需要"跨境 + 架构 + 信托"的组合能力，而不是单点产品 |
| **规则在 2026 年集中变化** | 离岸信托全生命周期课税（2026 年第 21 号公告，过渡期至 2026-10-22）；限售股规范（2026 年第 26 号公告，2026-08-28 起）；股权激励单独计税至 2027-12-31；大湾区 15% 补贴至 2027-12-31 | 规则时效性成为产品能力；靠人脑记规则必然出错 |
| **AI 已被接受为"副驾"，不是"主驾"** | 中国内地 95% 大众富裕及高净值客户已用 AI 辅助理财，但 >74% 坚持最终由人决策；机构测算 AI 可释放 25%–30% 产能、15%–20% 单顾问收入 | AI 的价值在中台与准备，不在客户端"机器人投顾" |

**结论**：私行的瓶颈不再是"有没有产品"，而是**从客户事件到可执行订单之间，有太多人工、太多口径、太多审批**。本方案就是把这段路修成一条可计算、可审计、可复用的工作流。

## 2. 设计目标（可验收）

| 目标 | 现状基线（公开口径 / 行业调研） | 12 个月目标 | 衡量方式 |
|---|---|---|---|
| 提案周转 | 美国 57% 从业者认为准备提案步骤太多、耗时太长（Avaloq 2026） | 从"天"降到"小时" | 提案创建 → 客户可看的时长 |
| 行政占用 | 行政与合规各占从业者约 54% 时间 | 下降 20 个百分点 | 时间日志 / 系统埋点 |
| 系统负担 | 香港仅 23% 从业者认为现有系统支持工作（各市场最低）；50% 使用 7 个以上系统 | RM 日常系统数 ≤ 3 | 系统接入统计 |
| 交易成本透明度 | 成本散落在佣金、点差、税、汇兑、托管 | 100% 提案出"全口径成本" | TES 覆盖率 |
| 合规返工 | 事后拦截、人工评审 | 生成阶段拦截 ≥ 80% | 规则命中率 / 返工率 |
| 客户体验 | 多辖区重复 KYC、账户不通 | 一次 KYC、多地叠加验证；开户周期 −30%–50%【目标值】 | 开户时长中位数 |

> 说明：上述"目标值"为方案建议值，不是承诺；基线来自公开调研，需以内部诊断校准。

## 4. 角色与职责（RACI 的简化版）

| 角色 | 在流程中的位置 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **Client** | 起点与终点 | 授权、确认目标、签署、查看报告 | — |
| **RM（Relationship Manager）** | 全程单一责任点 | 发起、编辑、选择方案、向客户交付 | 不代替合规签字；不做税务/法律意见 |
| **IC（Investment Counsellor）** | 提案与配置 | 校准假设、挑战结论、签字 | 不绕过适当性 |
| **Product Specialist** | 模板与条款 | 维护产品池、条款、定价 | 不直接向客户销售未授权产品 |
| **Quant / Model Owner** | M2 | 建模、回测、压力、模型文档 | 不把回测当预测 |
| **Compliance（含联动合规官）** | 规则与审批 | 规则版本、例外审批、跨墙审批 | 不进入分成池 |
| **Operations / Middle Office** | 订单与结算 | 校验、路由、确认、对账 | 不改提案实质 |
| **Tax / Legal Specialist（持牌第三方）** | 转介交付 | 出具意见、底稿 | 不由银行替代签署 |
| **Tax Optimization Specialist（内部）** | M5 | 画像、杠杆、情景、反避税、内部复核协调 | 出具内部复核意见；正式法律意见由内部持牌团队/外部律师出具 |
| **Trustee（HSBC TFS）** | M4 | 受托、分配、合规 | 不受 settlor 单方指令 |
| **Independent Valuer / Valuation Panel** | M4 | 独立估值、折扣、LTV 建议（10%–30%） | 不受 RM/客户影响；不直接放款 |
| **Vendor（乙方）** | M3 集采 | 按 RFP 投标、交付、开票 | 不接触客户金融数据；不直接获客 |
| **External Specialist（税务/法律/医疗等）** | M3 | 出具意见、交付服务 | 不由银行替代签署；不看未授权字段 |
| **AI（系统）** | 全流程 | 生成候选、解释、起草 | 不签字、不碰 MNPI、不直接对客户下结论 |

**单一责任点原则**：每位 T1/T2 客户只有一个 Lead RM；跨辖区团队是虚拟团队，不改变责任归属。转介 SLA：对公 → 私行 3 个工作日；内地 → 港/新 5 个工作日（建议值，沿用科技创始人报告 11.2 节）。

## 5. 端到端状态机（从事件到复盘）

```
[EVENT] 事件触发 / 客户请求 / 定期回顾
   │
   ▼
[S0] 识别与准入 ── KYC/KYB、AML、制裁、税务居民、适当性
   │  gate: 准入通过？ ──否──► 退出/补件（记录原因）
   ▼
[S1] 目标与约束 ── 目标、期限、流动性、集中度、币种、ESG、限制名单
   │
   ▼
[S2] 方案生成 ── 模板选择 → 三套候选 → TES 打分 → 解释
   │  gate: 是否有可行方案？ ──否──► 回到 S1（放宽约束需客户同意）
   ▼
[S3] 合规闸门 ── 四维规则、适当性、披露、跨墙
   │  gate: 红/黄/绿 ──红──► 终止；黄──► 例外审批（附条件）
   ▼
[S4] 客户确认 ── 提案书、风险揭示、电子签/双录
   │  gate: 签署完成？
   ▼
[S5] 订单计划 ── 母单拆子单、路由、算法、FX、资金校验
   │
   ▼
[S6] 执行与结算 ── 成交、分配、确认、交收、税基更新
   │
   ▼
[S7] 复盘 ── TCA、成本回写、模板校准、客户报告、下一次事件
```

**状态对象**：`Proposal(status)`：`DRAFT → SIMULATED → PENDING_REVIEW → APPROVED → CLIENT_SIGNED → EXECUTING → EXECUTED → SETTLED → CLOSED / CANCELLED / EXPIRED`。每一次状态迁移写 `EvidenceEvent`（谁、何时、依据、版本）。

**集成原则**
- **不替换核心系统**：在核心之上建"决策层 + 体验层"；核心仍是账本与交易的 system of record。
- **事件驱动**：客户、持仓、订单、规则、行情五类事件上总线；页面订阅，不轮询。
- **双向可追溯**：任一页面数字可下钻到源系统字段；任一源系统变更可回溯影响哪些提案。

## 7. 七个共享服务 + 两个专用服务（决定能不能规模化）

### S1 Client 360 / CDP
- **主数据**：个人、家庭、实体（控股公司/信托/基金）、账户、关系（实控人、受益人、授权人）、跨法域身份图谱（多证件、别名归一）。
- **三类标签**：公开标签（招股书/公告/工商）、授权标签（字段级、用途级、可撤回）、法定标签（AML/制裁/CRS）。
- **输出**：一个客户视图（汇总头寸、负债、非托管资产、事件、工单），字段级权限。

### S2 Product & Template Master
- 产品：ISIN、资产类别、法域、发行人、评级、期限、流动性、条款、费用、最低认购、适当性标签、限制名单状态。
- 模板：`template_id`、必填字段、成本项、税务处理、结算路径、适用法域/牌照、审批矩阵。

### S3 Rules Engine（四维）
- 维度：`jurisdiction × license × client_category × product_complexity`。
- 输出：`PASS / WARN / BLOCK` + 规则 ID + 依据 + 需补充的披露/审批。
- 版本化：每条规则带 `effective_from / effective_to / source`；规则变更不影响已签提案（快照）。

### S4 Cost & Tax Engine
- 成本：佣金、点差、市场冲击、印花税/交易税、过户费、托管费、平台费、汇兑、融资利息、结构化产品内含成本。
- 税：资本利得/所得税、预提税、协定、CRS/FATCA、印花税、遗产/赠与（适用时）、递延与损失抵扣。
- 输出：全口径成本（bps）、税后收益、税负时点、现金流。

### S5 Quant & Scenario Engine
- 配置：CMA、均值方差、Black-Litterman、风险平价、约束求解。
- 压力：历史情景、假设情景、反向压力、流动性情景。
- 回测：PIT 数据、含成本含税、样本外、deflated Sharpe、容量。
- 输出：区间而非点估计；假设与局限随结果一起输出。

### S6 Order Router / OMS
- 母单 → 子单（按 venue/算法/时间）、FX 对冲腿、资金校验、成交分配、TCA。
- 执行算法：TWAP/VWAP/POV/IS；大宗/询价走 block desk；FX 走询价或算法。
- 最佳执行：venue 分析、成交质量、成本对比。

### S7 Evidence Ledger + AI Gateway
- 记录：数据快照、规则版本、模型版本、提示词版本、生成内容、人工修改、审批人、客户披露版本、签署时间。
- AI Gateway：模型路由、PII 脱敏、提示词模板、输出 schema 校验、越界拦截、成本与延迟监控。
- **权限执行**：与 IAM/ABAC 共同执行 `08_permission_matrix.md` 的页面/字段/动作/行级规则；越权返回 403 并留痕。

### S8 Independent Valuation Panel（M4 专用）
- 独立估值机构选任、资料包、估值方法、折扣、委员会挑战、LTV 建议（10%–30%）、40% 触发线。
- 输出：估值报告、决议书、反对意见、可贷价值、前置条件。
- **不由系统自动定 LTV**；系统只记录委员会决议与理由。

### S9 Sourcing & RFP Engine（M3 专用）
- 需求聚合、vendor 准入、RFP、密封投标、评标、定标、合同、SLA、绩效。
- 输出：中标 vendor、合同、客户邀请（客户不看到价格/评分）。
- **客户不看到招标/比价过程**；专业服务禁止付费买排名。

### S10 Tax Optimization Engine（M5 专用）
- 税务画像、基线税图、杠杆库、簿记/实体比较、情景测算、反避税校验、内部复核、年度复盘。
- 输出：税后现金/有效税率/成本/风险、PASS/CONDITIONAL/REJECT、RM 决策卡。
- **不代替律师出正式法律意见**；无 HSBC PB 内部税务团队复核不交付；红灯即停。

## 9. 非功能要求

| 维度 | 要求 |
|---|---|
| 延迟 | 页面首屏 < 2s；TES 单方案 < 5s；压力测试 10 万路径 < 60s（异步） |
| 可用性 | 交易相关 99.95%；只读视图 99.9% |

| 可解释 | 任一建议可输出"数据 → 规则 → 计算 → 结论"四段链路 |
| 安全 | 字段级权限、最小必要、访问留痕、密钥托管、渗透测试 |

## 10. 与现状相比，改了什么（一张表）

| 环节 | 今天 | 本方案 |
|---|---|---|
| 提案 | RM 用 Excel/PPT 拼，口径不一 | 模板 + 生成器 + 统一成本/税口径 |
| 比较方案 | 靠经验与会议 | TES 五维打分 + Pareto 取舍 |
| 合规 | 事后评审、人工记忆 | 生成阶段四维拦截、规则版本化 |
| 量化 | 投顾单独跑模型，结果难解释 | Quant Lab 产出 RM 决策卡，假设随结果 |
| 融资 | 逐部门问、逐案审批 | Financing Cockpit：缺多少、能借多少、怎么还 |
| 税务/法律 | 靠外部关系、时点靠记 | 义务日历 + 情景 + 持牌转介 |
| 生活服务 | 零散、无标准 | 集采平台：HSBC 甲方、RFP、评标、SLA、客户邀请 |
| Pre-IPO | 上市后才接触 | Founder Desk：独立估值、托管、质押、变现、信托前置 |
| 估值/LTV | 系统参数或经验 | 独立估值委员会（PB-425）、LTV 10%–30%、40% 追保前置 |
| 信托消费 | 只做分配，不管税 | 分配税务台账（PB-465）：来源层、申报人、抵扣 |
| 变现决策 | 凭感觉比税率 | PB-445：税后终端财富、盈亏平衡 `r*`、−40% 下行 |
| 税务优化 | 靠外部顾问单点咨询 | M5：画像、杠杆、情景、反避税、HSBC 内部复核、RM 交付 |
| 权限 | 页面级、靠人管 | 角色×页面×字段×动作矩阵（`08_permission_matrix.md`） |
| 复盘 | 事后补材料 | TCA 自动回写、模板校准 |
