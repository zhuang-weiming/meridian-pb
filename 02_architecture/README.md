## 这份文档做什么

从 21 个案例（20 组公开 + 1 组匿名）的痛点出发，而不是从竞品功能清单出发，回答三个问题：

1. **客户为什么痛？** 21 个案例 → 8 个 Job（看见 / 行动 / 归属 / 合规 / 变现 / 传承 / 证明 / 服务）→ 25 条痛点（原有 10 条 + 增量 15 条）。
2. **客户愿意为哪个痛付钱？** 区分 T1 客户付溢价/信贷、T2 打包/留存、T3 必须有但不能单列收费、T4 纯基础设施。
3. **系统应该长什么样？** 7 层、18 个模块；建设顺序与风险验证留待下一阶段。

## 核心结论

- **需求强度 ≠ 付费意愿，也不等于不可逆性。** 最痛的是授权、合规、证据、数据一致性；最愿意付钱的是流动性、家族治理、税务协调、私人股权；最不可逆的是失能/身故与文件生效链。
- **Avaloq 必须被平替，但不是“它什么都没有”。** 它的强项是账务、结算、税表工程；CRM 对投资账户有账户/授权/受益人/决策人四类记录、信托定义清楚，税务能算能报。真正的差距是：四类记录是账户级、静态的，失能/身故当天不联动；税务的“计算/申报/缴税/建议”四层没有分开；生态合作与私股自动化没有对象。平替的验收标准仍是：关掉 Avaloq 之后，8 个 Job 仍能交付。
- **六个收入模块：** M02 家族治理、M03 授权/争议、M05 权利矩阵、M06 私人股权、M10 信贷与流动性、M13 税务计算。
- **UBS 对标结论：** 差距不是“有没有”，是“产品化/平台化/一体化”；补 G1 目标规划、G2 慈善平台、G3 私募运营，G4/G6 用合作与服务设计补齐。
- **十二个成本/地基模块：** 客户主数据、实体结构、资产登记、IBOR、交易、支付、身份状态、义务披露、案件、证据、数据平台、AI。
- **不建：** 自建风险分析（买 Aladdin）、全量 held-away 聚合（合作 Addepar）、通用 AI Copilot 底座（买平台）、大众市场 onboarding；数字资产/加密暂不纳入（含读侧），如需外购。

## v1.4 变更（相对 v1.3）

- **接入 personas v3.5**：§18–§21 四个财富带案例（Ali Abdaal、Nadiya Hussain、Alvin Leung、Hawker Chan）进入 8 个 Job 的映射；§1 从“17 组”改为“21 个案例”。
- **新增 §2.8“Avaloq 一线的四条修正”**：① Avaloq CRM 对投资账户确有账户/授权/受益人/决策人四类记录、信托定义清楚，但四记录是账户级、静态的，失能/身故当天不联动；② 税务必须拆成**计算/申报/缴税/建议**四层，EasyTax 只做申报，缴税是否含在 Avaloq 内须厂商确认，HSBC 主要做 CRS/FATCA 尽调；③ RM 私下推荐会计师/律师/家办 = 无记录、无同意、无责任边界，必须对象化；④ Pre-IPO/私股大量手工，自动化只到“可计算、可监控、可举证”，估值判断/授信审批/谈判/法律意见仍由人。
- **新增 §4.5 生态合作与数据复用**：不新增模块，新增 `PartnerRegistry`、`ReferralCase`、`EvidencePack`、`DataSharingConsent`、`NextBestAction`；明确“客户 A 的原始信息不得直接服务客户 B”，只允许去标识化/聚合模式；给出 L1 同客户跨实体 / L2 同类客户模式 / L3 对外合作方三层边界。
- **新增 §5.3 Pre-IPO/私股自动化边界**：逐环节列出“今天怎么手工做 / 可自动化 / 必须人审 / 风险与证据”，并给出估值、流动性/退出、法律/执行三个不能越过的风险线。
- **修正 §6.1 的过重表述**：Avaloq 不是“没有四类记录/完全不碰税”，差距在事件级联动与四层税务边界；新增“生态合作”一行。
- **§4.1 增第八条原则“合作而不越界”**；M03/M06/M10/M13/M14/M15/M16/M17/M18 的能力行与对象同步；§7.1 明确生态合作不直接收费。

## 18 个模块

| 层 | 模块 |
|---|---|
| L1 客户与家庭 | M01 客户/家庭主数据、M02 家族图谱与治理、M03 同意/授权/争议 |
| L2 结构、权利与资产 | M04 实体与结构图、M05 权利与所有权、M06 私人股权与 Pre-IPO、M07 资产/负债登记 |
| L3 产品与流动性 | M08 组合与 IBOR、M09 交易/执行/预检、M10 信贷与流动性、M11 支付与外汇 |
| L4 税务、监管与义务 | M12 多辖区身份状态、M13 税务计算与申报、M14 义务/披露/报告 |
| L5 运营与证据 | M15 案件与工作流、M16 文件/契约/证据 |
| L6 数据、AI 与集成 | M17 客户数据平台与集成、M18 AI Copilot 与监督 |

## 使用边界

- 评分为序数（1–5），用于排序，不用于报价；所有金额、比例均为示意假设。
- 正式立项前须用 10–15 个客户访谈、5 场 RM 工作坊、3 个辖区税务/法律验收校准。
- 不构成税务、法律或投资建议；税务模块只做计算、申报包与协调，不做缴税承诺与税务意见（缴税走支付/税务代理接口）。
