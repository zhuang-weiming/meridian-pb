# 00 — 用户旅程框架：从痛点到 Demo 的五段链

> 这份文件定义 D1–D7 共用的写法。每条旅程都按同一顺序展开，领导听到的是故事，系统组看到的是需求，架构组看到的是“继承 / 扩展 / 新建 / 合作”的决策。

---

## 1. 五段链（每条旅程的主骨架）

```
痛点（Pain）
  → 新客户体验（Client Experience）
  → 系统体验（System Experience）
  → 功能需求（Functional Requirements）
  → Avaloq 改造/重写 / Aladdin 复用 / 新增（Build Decision）
```

| 段 | 回答的问题 | 在 Demo 里的表现 | 在架构里的落点 |
|---|---|---|---|
| **痛点** | 今天哪一天、哪一件事让客户/银行痛？ | 一条时间线、一个失败链、一个代价 | 痛点 #、类别、Job |
| **新客户体验** | 客户看到什么、能做什么、不用再做什么？ | 客户视角的 2–3 屏 | X1/X2/X4 |
| **系统体验** | RM/系统看到什么？哪些对象/状态/证据在流动？ | 工作台视角的 2–3 屏 | M01–M18、对象 |
| **功能需求** | 系统必须回答什么、必须记住什么？ | 一张“对象 × 模块”表 | 对象、规则、验收 |
| **建设决策** | 哪些继承 Avaloq、哪些扩展、哪些新建、哪些合作？ | 一张四色决策表 | Avaloq / Aladdin / Addepar / 合作方 |

---

## 2. 建设决策：四选一，不搞“全自建”

| 决策 | 含义 | 典型能力 | 在文档里的写法 |
|---|---|---|---|
| **继承（Inherit）** | Avaloq 已经做好，不重写；只接接口/数据 | 结算/多登记、文档版本、集团墙、税务扣缴、entitlement/ACL、CRM 联系方式/家庭关系 | “继承 Avaloq，不重写” |
| **扩展（Extend）** | Avaloq 有基础，但缺语义/事件/辖区规则；加对象/规则 | 集团墙的辖区规则、税务规则包、文档冲突裁决、CRM → 独立客户/服务历史 | “在 Avaloq 之上扩展” |
| **新建（Build）** | Avaloq 没有一等对象，且这是差异化/护城河 | EconomicInterest、EventSnapshot、ValuationGovernance、ServiceHistory/Handover、Partner/Evidence/Consent、ChannelIdentity | “新建语义层” |
| **合作（Partner）** | 别人做得更好、更便宜；不重复投入 | Aladdin 风险/组合分析、Addepar held-away/合并、外部估值师、税务/法律合作方、渠道 APP | “买/合作，不自建” |

**判断顺序：**
1. Avaloq 是否已有一等能力？→ 有：继承。
2. 有基础但缺事件/语义/辖区规则？→ 扩展。
3. 没有，且是客户付费时刻/证据链？→ 新建。
4. 商品化/专业判断在别处？→ 合作。

## 3. Demo 的戏剧结构（每条旅程 2–4 分钟）

| 幕 | 时长 | 内容 | 目的 |
|---|---|---|---|
| **钩子** | 15–20 秒 | 一个具体时刻：“2026 年 11 月 3 日，何先生手术后第 3 天……” | 让领导先“看见人” |
| **今天** | 40–60 秒 | 失败链：银行 3–30 天才知道、家属垫资、Excel、probate 2–3 个 | 让领导承认“这真的会发生” |
| **明天** | 60–90 秒 | 客户视角 2 屏 + 系统视角 2 屏 | 让领导看见“新体验” |
| **揭示** | 30–45 秒 | 一张对象/模块图 + 一张 Avaloq 决策表 | 让领导知道“不是 UI，是核心系统” |
| **证据** | 15–20 秒 | 一条 as-of 证据链/一个 KPI | 让领导相信“可交付、可审计” |

**一条旅程只留一个“wow”**：
- D1：T+0 权限快照（失能当天，系统已经知道谁能签字）。
- D2：同一个人、同一天、两张税表（且能重放）。
- D3：不卖股也能拿到钱（质押/估值/追保一条链）。
- D4：四个视角合并敞口，但墙的方向可见、可阻断、可留痕。
- D5：$2–5m 客户不用 18 个模块全量服务（成本-to-serve 成立）。
- D6：品牌/担保/租约/股权在一张图上（退休前知道哪些能关、哪些会追到个人）。
- D7：跨渠道 deepfake 被阻断，且 24 小时内能还原证据链。

## 4. 真实性规则（2024–2026）

1. **公开人物只用公开事实**：引用日期、来源、事件；不编造账户、金额、税务安排、家庭矛盾。
2. **AUM/费率/服务模型是设计假设**：在文件开头用“设计假设”标注；不说“某人是本行客户”。
3. **时间贴近 2024–2026**：Ali 2024 移居香港；Nadiya《Quick Comforts》2026-02；梁文锋 2026-06 融资；Alvin aKin 2025 一星；Hawker 2021 失星、2023 30+ 门店；许家印信托案 2025-09。
4. **匿名/合成要标明**：何氏家族是匿名结构；D7 是合成客户；不伪装成公开人物。
5. **法律/税务结论只写“事实 + 到期日 + 责任方”**：不写建议；边界由税务/法律组复核。

## 5. 交给 03_webpage_design 的接口

每条旅程的“Demo 分镜”就是未来的页面脚本。一个分镜至少给：

- **屏幕标题**（客户视角 / RM 视角）
- **第一眼看到的一个数字/状态**
- **一个动作**（点击、滑动、批准、拒绝）
- **一个系统对象**（如 `EventSnapshot`、`TaxResidencyTimeline`）
- **一个证据**（as-of、版本、授权、规则）

> 03 只需要把这些分镜变成 HTML；不需要重新理解业务。02.1 不写 CSS/JS，也不改 03 的现有页面。

## 6. 一条旅程的验收（示例）

| 维度 | 验收问题 |
|---|---|
| 客户 | 客户能不能在 1 屏内回答“我现在能做什么/不能做什么”？ |
| RM | RM 能不能在 1 屏内回答“谁有权、依据哪份文件、下一步是谁”？ |
| 系统 | 系统能不能在 T+0 给出快照，并在 T+90 重放同一结论？ |
| 建设 | 这张决策表是否明确“继承/扩展/新建/合作”，且没有把 Avaloq 强项重写？ |
| 证据 | 任一结论是否能输出“事实 + 义务/到期日 + 责任方 + 证据”？ |
