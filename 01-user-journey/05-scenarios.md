### S1 — 教育目标与复利：从“一笔钱”到“18 年计划”

#### S1.1 主角与触发

- 何启明 62 岁，家族企业创始人；妻子陈雅仪 59 岁，家庭 CFO；孙女何一诺 6 岁。
- 家族目标：为一诺准备 **US$2m** 教育金（英国/香港/美国三条路径），18 岁可用；同时不影响家族企业现金流。
- 触发：一诺上小学；家族想“现在开始，不要到时临时卖资产”。

#### S1.2 目标与约束

| 维度 | 内容 |
|---|---|
| 目标 | 18 岁时 US$2m（今天币值）；可选英国/香港/美国 |
| 时间 | 12 年 |
| 风险 | 不能大亏；回撤 ≤15%；每年可补足 |
| 流动性 | 每年最多用 4%；教育金不动本金 |
| 税务 | 香港税务居民；信托/赠与/跨境需顾问 |
| 治理 | 父母出资；祖母/父母/孩子不同视图；孩子 18 岁后逐步参与 |

#### S1.3 现状失败链

| 问题 | 今天 | 代价 |
|---|---|---|
| 目标 | 没有“教育金”对象；只有几个账户/产品 | 不知道够不够 |
| 复利 | 每年看收益率，没有 12 年现金流 | 容易追涨杀跌 |
| 信托 | 信托预算/分配靠 Excel | 分配/税/证据不清 |
| 家庭 | 父母/祖母/孩子看到不同报表 | 家庭会议各说各话 |
| 年度 review | RM 靠 PPT | 没有“目标 vs 实际” |

#### S1.4 新体验（客户 4 屏）

1. **教育目标卡**：US$2m、12 年、三条路径、当前 funding ratio 78%。
2. **复利/情景**：5% 现实/3% 保守/7% 乐观；回撤/补足计划。
3. **年度回顾**：实际 vs 目标、费用、税、信托分配、下一步。
4. **家庭视图**：父母看全图；祖母看孙辈；孩子 18 岁后看自己的账户/学习。

#### S1.5 系统对象

`Goal`（education）、`GoalFunding`、`CashflowPlan`、`Portfolio`、`IPS`、`TrustBudget`、`BenefitPayment`、`AnnualReview`、`NextGenAccount`。

#### S1.6 建设决策

| 能力 | 决策 |
|---|---|
| 组合/交易/账本 | Avaloq |
| 风险/情景 | Aladdin |
| 目标/现金流/年度 review | 新核心 |
| 信托预算/分配 | TFS + 新核心 |
| 家庭视图/下一代 | 新核心 |

#### S1.7 好结果

- 12 年后 funding ratio **105%**；一诺拿到英国/香港 offer；信托按预算支付；本金仍在。
- 家庭每年一次“同一张图”会议；孩子 18 岁开独立账户、完成首投/慈善。
- 银行获得：教育金 AUM、信托关系、下一代主关系、转介。

#### S1.8 指标

目标达成率、补充率、回撤恢复、年度 review 出席、下一代独立账户/首投。

#### S1.9 边界

不承诺收益；情景为假设；税务/信托由顾问/受托人确认。

### S2 — 二代创业：不接班，也能用家族资源

#### S2.1 主角与触发

- 何俊轩 28 岁，创始人之子；在伦敦/香港做 **时尚/消费科技** 品牌；不愿直接接家族企业。
- 触发：品牌准备种子轮；需要独立账户、股权结构、供应商融资、导师、家族投资决策。

#### S2.2 目标与约束

| 维度 | 内容 |
|---|---|
| 目标 | 3 年内做到区域品牌；首轮 US$3m |
| 家族 | 家族可投 US$500k，但要有投资政策/上限/退出 |
| 独立 | 俊轩要独立，不想被父母控制 |
| 银行 | 独立账户、支付、外汇、融资、导师、HSBC Access/Innovation Banking |
| 治理 | 家族投资委员会/宪章；失败怎么办 |

#### S2.3 现状失败链

| 问题 | 今天 | 代价 |
|---|---|---|
| 独立 | 俊轩用父亲的关系/账户 | 权责不清 |
| 股权 | cap table 用 Excel | 融资/稀释/税出错 |
| 融资 | 银行只看抵押/担保 | 创业公司拿不到钱 |
| 家族 | “给不给钱”靠饭桌 | 家庭冲突 |
| 生态 | 没有导师/客户/投资人 | 增长慢 |

#### S2.4 新体验（客户 4 屏）

1. **独立身份**：俊轩是独立客户；自己的账户/consent/风险偏好；父母看不到明细（除非同意）。
2. **创业仪表盘**：cap table、 runway、融资、供应商、外汇、保险。
3. **家族投资政策**：家族可投多少、什么条件、谁决定、失败怎么办；有记录。
4. **生态入口**：导师、HSBC Access/Innovation Banking、CIB 客户、行业活动。

#### S2.5 系统对象

`NextGenProfile`、`Venture`、`CapTable`、`Guarantee`、`Mentor`、`FamilyInvestmentPolicy`、`Consent`、`Referral`、`AccessOpportunity`。

#### S2.6 建设决策

| 能力 | 决策 |
|---|---|
| 独立账户/支付/外汇 | Avaloq |
| 创业融资/担保 | Avaloq 信贷 + 新核心 |
| 家族投资政策/决策 | 新核心 |
| 导师/生态/Access | 合作/CIB |
| 下一代 app | 新核心 |

#### S2.7 好结果

- 首轮 **US$3m**（家族 US$500k + 外部）；12 个岗位；进入 HSBC Access 生态；俊轩成为独立客户。
- 家族投资政策/宪章落地；父母/子女关系更好；银行获得下一代主关系、创业融资、家办。

#### S2.8 指标

首轮融资、独立账户、家族投资决策记录、导师匹配、下一代 NPS、5 年留存。

#### S2.9 边界

不承诺融资/估值；创业失败是可能的；银行不做创业建议；担保/信贷按风险审批。

- 银行获得：跨 3 辖区关系、存款/按揭/投资/信托。

### X1 — 失能：人在世，但没有 probate

#### X1.1 触发

- 何启明 62 岁，中风；意识清楚但认知受损；医生评估“无法处理复杂财务”。
- 家族要付医疗、护工、员工工资、贷款利息；妻子陈雅仪是家庭 CFO，但不是账户持有人。
- 只有一份 2019 年的一般 POA（未登记、权限有限）；没有 LPA/EPA；没有法院 deputy。

#### X1.2 法律链

| 问题 | 答案 |
|---|---|
| 人在世还是身故？ | 在世；**没有 probate** |
| 谁有权？ | 若 POA 有效且登记：代理人；若无效/无：法院任命的 deputy/committee；若争议：法院 |
| 一般 POA 能否覆盖失能后？ | 视辖区/文书；HSBC UK 的 general POA 明确不能在失能后管理账户 |
| 银行能否向家属披露？ | 不能，除非有授权/法院命令/合法例外 |
| 银行能否紧急付款？ | 按政策/法院命令/授权；不是“家属说了算” |
| 信托资产？ | trustee 按信托契约；不是代理人/家属可直接动 |
| 跨境？ | 各辖区承认/执行不同；可能需要 local court/legal opinion |

#### X1.3 现状失败链

| 时点 | 今天 | 失败点 | 代价 |
|---|---|---|---|
| T0 | 系统仍显示何启明是 decision-maker；POA 是扫描件在 RM 邮箱 | 没有 authority 状态 | RM 不知道谁能签字 |
| T+1 | 妻子到分行，被告知“需要 POA/法院文件” | 没有“授权缺口清单” | 家属反复跑 |
| T+3 | 医疗/工资/利息到期；账户被限制；RM 帮不上 | 没有紧急支付裁决 | 家属垫资/借款/卖资产 |
| T+7 | 律师说一般 POA 可能不够；要申请 deputyship | 没有法律路径图 | 数周–数月 |
| T+30 | 香港/新加坡实体各自要文件；信托另有一套 | 没有跨实体编排 | 重复 KYC/延误 |
| T+90 | 家属不知道“下一步谁做” | 没有 case owner | 关系恶化/投诉 |

#### X1.4 新体验（客户 4 屏）

1. **家庭权限地图**：谁现在能做什么/不能做什么；哪些需要法院；哪些银行可以自主决定。
2. **90 天现金计划**：医疗、护工、工资、利息、税；哪些可付、哪些冻结、缺口多少。
3. **授权缺口清单**：缺哪份文件、哪个辖区、哪个机构、预计多久、谁负责。
4. **下一步时间线**：银行/律师/法院/信托各自的任务与到期日。

#### X1.5 系统对象

`CapacityEvent`、`Authority`、`AuthorityScope`、`AuthorityGap`、`CareExpense`、`EmergencyPayment`、`CrossEntityCase`、`CommunicationLog`、`EvidencePack`。

#### X1.6 建设决策

| 能力 | 决策 |
|---|---|
| 账户/支付/余额 | Avaloq |
| 授权登记/权限矩阵 | 新核心 |
| 失能案件/缺口/时间线 | 新核心 |
| 客户/家属 portal | 新核心 |
| 医疗/法律评估 | 合作 |
| 文档 vault | 自研新核心证据库 |

#### X1.7 指标

15 分钟 authority snapshot；24 小时“可付/不可付/缺口”；0 无权支付；缺口清单 100% 责任方/到期日；家属 NPS；30 天法律路径确定率。

#### X1.8 负向需求

- 不跑 probate（人在世）；
- 不把“家属一致同意”当授权；
- 不在授权前披露余额/受益信息；
- 不承诺“银行可以绕过法院”；
- 不把信托资产当个人资产；
- 不未经批准跨境传输。

### X2 — 身故/遗产：死亡不是“一个时点”，是 20 年现金流

#### X2.1 触发

- 何启明去世；葬礼 7 天内；遗嘱指定妻子为 executor；香港/新加坡/英国资产；香港信托；联名账户；公司股权。
- 家族预期“有遗嘱就能取钱”；银行知道需要 grant。

#### X2.2 法律链

| 问题 | 答案 |
|---|---|
| POA 还有效吗？ | 死亡即终止 |
| 谁有权？ | executor（遗嘱）/ administrator（无遗嘱）；完整权限通常等 grant |
| 银行能做什么？ | 记录死亡、保护资产、告知流程、验证文件、在允许范围内付 funeral/urgent；开 estate account 等 |
| 信托资产？ | trustee 按信托契约；不是遗产 |
| 联名账户？ | 可能转 survivor；取决于受益权/当地法 |
| 跨境？ | 本地 grant/reseal/承认；一个 grant 不一定全球有效 |
| 家庭供养？ | 依赖人可能依成文法申请；需预留 |

#### X2.3 现状失败链

| 时点 | 今天 | 失败点 | 代价 |
|---|---|---|---|
| T0 | 家属打给 RM；RM 说“节哀，我帮你转 bereavement” | 没有统一死亡事件 | 信息重复 |
| T+1 | 不同实体要死亡证明/遗嘱/ID；家属重复提交 | 没有跨实体 case | 时间/情绪成本 |
| T+3 | 葬礼要钱；账户冻结；家属垫资 | 没有 funeral/urgent 支付规则 | 家庭冲突 |
| T+7 | 律师说香港 probate 要几周；英国/新加坡另跑 | 没有 probate tracker | 预期失控 |
| T+30 | 信托说“这不是遗产”；银行说“等 grant” | estate/trust 不分 | 争议/诉讼 |
| T+90 | 受益人/税务/公司股权/联名账户一团 | 没有 estate ledger | 漏资产/漏债/罚款 |

#### X2.4 新体验（客户 4 屏）

1. **死亡事件时间线**：通知、文件、POA 终止、executor 授权、grant、estate account。
2. **Estate/Trust 双地图**：哪些资产进遗产、哪些进信托、哪些走 nomination/joint。
3. **90 天现金计划**：funeral、医疗、税、债、家庭生活费；哪些可付、哪些等 grant。
4. **跨境 probate 追踪器**：香港/英国/新加坡；文件、法院、到期日、责任方、承认状态。

#### X2.5 系统对象

`DeathEvent`、`AuthorityRevocation`、`EstateCase`、`ProbateCase`、`TrustCase`、`EstateAccount`、`BenefitPayment`、`DependantClaim`、`CrossBorderCase`、`EstateExpense`、`EvidencePack`。

#### X2.6 建设决策

| 能力 | 决策 |
|---|---|
| 账户/支付/余额 | Avaloq |
| 死亡/遗产/信托案件 | 新核心 |
| 跨境 probate/命令 | 新核心 |
| estate/trust 双账本 | 新核心 |
| 文档/证据 | 自研新核心 |
| 法律/信托/估值 | 合作/TFS |

#### X2.7 指标

1 小时确认死亡通知；24 小时授权/文件清单；5 工作日“可付/不可付/缺口”；grant 后 10 工作日 estate account/首笔；0 无权支付/披露；100% 资产/负债地图；投诉率/NPS；estate 关闭周期/成本。

#### X2.8 负向需求

- 不在 grant 前把资产转给家属；
- 不把信托资产当遗产；
- 不向无权家属披露；
- 不承诺“几天拿钱”；
- 不忽略家庭供养/依赖人；
- 不未经批准跨境传输/税务申报。

### X3 — 离婚 / 监狱 / 制裁：法律与声誉冲击

> 说明：这是设计场景，不指任何真实个人；监狱/制裁/刑事调查都可能发生，银行必须合法、冷静、可证据。

#### X3.1 三种变体

| 变体 | 触发 | 银行要做什么 | 不能做什么 |
|---|---|---|---|
| **离婚** | 配偶申请离婚/财产披露 | 按法院命令/授权披露；区分个人/信托/公司；保护受益人；冲突检查 | 不擅自冻结/披露；不偏袒一方；不把信托资产当婚姻财产 |
| **刑事/监狱** | 客户/关联人被调查/羁押/入狱 | 确认授权/签字权；制裁/PEP/负面新闻；法院/监管要求；资产保护 | 不歧视/不擅自冻结；不泄露；不做有罪推断 |
| **制裁/PEP** | 客户/关联人命中制裁/PEP | 冻结/限制/上报；来源/目的/受益所有人；退出/剥离 | 不绕过制裁；不拆分交易；不隐瞒 |

#### X3.2 法律链

- 授权：被羁押/入狱不等于失去 capacity；POA/公司授权/法院命令决定谁签字。
- 制裁：资产冻结/交易限制；银行有报告义务；不能“先放款再补”。
- 离婚：披露范围由法院/法律决定；信托/公司/受益人分离；不要“客户说不要给”就拒绝法院。
- 声誉：负面新闻不等于法律结论；需要证据/法律意见/升级。

#### X3.3 现状失败链

| 问题 | 今天 | 代价 |
|---|---|---|
| 授权 | 家属/公司/律师各说各话 | 无权支付/越权 |
| 制裁 | 事后发现 | 罚款/声誉 |
| 披露 | RM 凭关系 | 诉讼/隐私 |
| 资产 | 个人/公司/信托混 | 错冻/错放 |
| 证据 | 邮件/口头 | 无法证明 |

#### X3.4 新体验（RM/合规 4 屏）

1. **法律状态图**：谁被调查/羁押/制裁；哪些实体/资产受影响；哪些授权仍有效。
2. **授权/法院命令**：谁签字；范围；生效/失效；法院/监管要求。
3. **资产隔离**：个人/公司/信托/受益人；哪些可动/不可动。
4. **证据/沟通**：对谁说了什么；披露依据；不披露依据；上报。

#### X3.5 系统对象

`LegalStatus`、`SanctionsHit`、`PEPStatus`、`CourtOrder`、`Authority`、`AssetFreeze`、`DisclosureRequest`、`ConflictRegister`、`EvidencePack`。

#### X3.6 指标

制裁筛查及时率、0 违规支付、披露合规、法律费用、声誉事件、客户留存。

#### X3.7 负向需求

- 不做有罪推断；
- 不绕过制裁/法院；
- 不向无权家属/媒体披露；
- 不拆分交易规避；
- 不擅自冻结/解冻；
- 不把“客户关系”当披露依据。

### X5 — 欺诈/深伪：一笔“RM 视频”的转账

#### X5.1 触发

- 客户/财务收到“RM 视频/邮件”要求紧急转账 US$5m 到供应商；视频是深伪；邮件域名相似。
- 客户/财务已部分授权；银行发现异常（新收款人/高风险辖区/时间压力/设备变更）。

#### X5.2 法律链

- 授权：客户授权不等于银行免责；可疑指令需查询/升级（Quincecare）。
- 欺诈：APP 欺诈/授权推送支付；银行/客户责任取决于法律/规则。
- 证据：设备/行为/收款人/沟通/客户确认。
- 赔付：按法律/规则/保险/商业决定。

#### X5.3 现状失败链

| 问题 | 今天 | 代价 |
|---|---|---|
| 授权 | 只看密码/OTP | 深伪绕过 |
| 异常 | 事后 | 钱已走 |
| 沟通 | 邮件/电话 | 无法证明 |
| 赔付 | 争议 | 声誉/成本 |

#### X5.4 新体验（客户/风控 4 屏）

1. **交易风险卡**：收款人/辖区/金额/设备/行为/时间；红黄绿。
2. **多因子确认**：回拨已知号码/视频活体/双人复核；不是“再发一次 OTP”。
3. **拦截/延迟**：高风险支付延迟/人工复核；客户通知。
4. **证据包**：谁/何时/什么设备/什么指令/谁批准/如何拦截。

#### X5.5 系统对象

`FraudCase`、`Authorization`、`Anomaly`、`PaymentHold`、`CustomerConfirmation`、`EvidencePack`、`Reimbursement`。

#### X5.6 指标

拦截率、误杀率、赔付率、客户 NPS、监管/警方合作、追偿。

#### X5.7 负向需求

- 不歧视/不擅自冻结全部资产；
- 不泄露风控规则；
- 不让客户“自己承担全部”；
- 不用“OTP 已发”当唯一证据；
- 不延迟合法紧急支付（需平衡）。

### X6? — 为什么没有“监狱”单独一条

监狱/刑事调查被并入 X3（法律/声誉冲击），因为它不是一个独立的“产品旅程”，而是“授权/制裁/披露/声誉”的组合。单独做成一条容易变成“猎奇”，也不符合私行的“家族信任”叙事。
