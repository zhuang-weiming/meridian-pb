## 3. 建设决策汇总：哪些继承、哪些新建

| 决策 | 能力 | 说明 |
|---|---|---|
| **继承** | 结算/多登记、文档版本、集团敞口/墙、税务扣缴/缴纳、entitlement/ACL、CRM 联系方式/家庭关系 | Avaloq 的真实强项；不重写 |
| **扩展** | 辖区墙规则、税务规则包（UK/HK/CN）、文档冲突裁决、婚姻/监护、费用披露、制裁/UBO、基金会、私人股权质押 | 在 Avaloq 基础能力上加语义/事件/辖区规则 |
| **新建** | `EconomicInterest`、`EventSnapshot`、`ValuationGovernance`、`ServiceHistory/Handover`、`Partner/Evidence/Consent`、`ChannelIdentity`；以及 `ProbateCase`、`AuthorityDocument`、`IncomeStream/RoyaltyStream`、`PersonalGuarantee/BrandAsset/FranchiseAgreement/Lease`、`FraudCase` | 客户付费时刻 + 证据链；这是差异层 |
| **合作** | Aladdin（风险/组合/情景）、Addepar（held-away/合并）、外部估值师、税务/法律顾问、制裁/PEP 数据、PB/Premier APP | 商品化/专业判断在别处；不重复投入 |

## 4. 一句话给领导

> **25 条痛点不是 25 个功能，而是 7 个“客户最需要银行”的时刻。**
> 每个时刻都走同一条链：客户体验 → 系统体验 → 功能需求 → 继承/扩展/新建/合作。
> 我们不是重写 Avaloq；我们是在它已经做好的结算、文档、墙、扣缴、ACL 之上，补六个语义对象，让银行在客户最脆弱/最需要钱的那一天不出错。
