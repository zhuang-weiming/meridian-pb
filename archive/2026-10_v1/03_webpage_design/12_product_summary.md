# 12 — 产品总览：流程、页面与字段索引

> 这份文件是给管理层/产品/科技的一页式总览：**五个用例、48 个页面、一条端到端流程、一套权限与证据底座**。详细字段见各模块文档。

---

## 1. 产品是什么

**HSBC Private Bank**：把私行的"提案、下单、量化、顾问、创始人服务、税务优化"从六个系统、六种口径、六道人工审批，改造成**一条以客户事件为起点、以税后结果为目标函数、以合规规则为硬约束、以证据链为审计底稿**的工作流。

**范围（本版）**：香港 + 新加坡。内地不作为销售/招揽市场；中国税务居民的跨境税务/CRS/21 号公告/数据出境按客户身份处理。

**AI 的位置**：生成候选、解释取舍、准备材料；不签字、不碰 MNPI、不自算数字、不直接给客户下结论。

## 3. 端到端流程（一条主线，五个入口）

```
客户事件（解禁/IPO/分红/迁居/年结/新投资）
   │
   ├─► M1 提案 → 订单：目标/约束 → 模板 → 3 套方案 → TES → 执行蓝图 → 合规 → 签署 → 订单 → TCA
   │
   ├─► M2 量化：问题 → IPS → 配置 → 压力 → 回测 → 交易影响 → RM 决策卡
   │
   ├─► M3 副驾：融资缺口 → 额度/抵押 → 税务/法律清单 → 服务匹配 → 客户邀请 → 案件
   │
   ├─► M4 创始人：资产 intake → 独立估值 → 托管/质押 → 变现/质押 vs 卖出 → 信托 → 消费/税务台账 → 复盘
   │
   └─► M5 税务优化：画像 → 基线 → 杠杆 → 簿记/实体 → 情景 → 反避税 → HSBC 内部复核 → RM 决策 → 交付/复盘
```

### 3.1 五个关键"闸门"

| 闸门 | 在哪个模块 | 不通过会怎样 |
|---|---|---|
| **准入/适当性** | M1 PB-160 | 不能生成/签署 |
| **TES/成本** | M1 PB-140 | 不能比较/推荐 |
| **四维合规** | M1/M5 | BLOCK 不可覆盖 |
| **独立估值/LTV** | M4 PB-425 | 不能放款；LTV 不由系统设定 |
| **反避税/内部复核** | M5 PB-560/570 | 红灯即停；无复核不交付 |

## 5. 角色与权限（一页版）

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| **Client** | 看自己的提案/邀请/信托报告；反馈 | 看内部笔记/其他客户/其他受益人 |
| **RM** | 发起、编辑、选择方案、交付 | 不批自己客户授信；税号掩码；不看 MNPI |
| **IC** | 配置、挑战、签字 | 不释放订单；不看税号/健康 |
| **Compliance** | 规则、审批、调查、解密、冻结 | 不改订单/提案；不进分成 |
| **Credit** | 抵押、LTV、额度、追保 | 不看信托分配/税务 |
| **Trustee** | 信托资产、分配、申报 | 不看客户个人账户 |
| **Vendor** | 投标、交付、开票 | 不看客户姓名/持仓/其他投标 |
| **Tax Optimization Specialist（HSBC 内部）** | 画像、杠杆、情景、反避税、客户交付支持 | 不出法律意见；不直接对客户下结论 |
| **AI** | 白名单检索、草稿 | S3/S4/S5、导出、签字、下单 |

**四条 SoD**：提案 ≠ 审批；授信 ≠ 关系；受托决议 ≠ 付款复核；评标 ≠ 定标。

## 6. 本版的八个设计决定

1. **提案双层**：提案层三套方案；执行层逐行蓝图；行级变更超阈值回提案层。
2. **TES 五维**：成本 25 / 税后 20 / 时间 20 / 冲击 20 / 可执行性 15；只做同次比较。
3. **服务与邀请**：HSBC 提供/协调；采购是后台，不在客户邀请页展示；客户免费、不看价格/评分；超出免费范围客户直接签约、与 HSBC 无关。
4. **LTV 10%–30%**：独立估值委员会决定；40% 下跌触发追保写入放款前置。
5. **信托消费**：信托持有 + 使用协议 + 受托人直付 + 小额现金；不做"随便花"。
6. **税务台账**：分配来源 C1–C6、谁申报、税额抵扣、21 号公告映射；无来源/无意见/无凭证不付款。
7. **质押 vs 卖出**：比税后终端财富、盈亏平衡 `r*`、−40% 下行；不把质押说成免税。
8. **税务优化 M5**：合法优化、反避税红灯、HSBC PB 内部税务团队复核、RM 审核后交付；不做"藏钱"。

## 7. 上线顺序（建议）

| 阶段 | 时间 | 上线 | 验收 |
|---|---|---|---|
| **P0 地基** | 0–6 月 | Client 360、模板/产品、规则、成本/税、证据账本、权限矩阵 v1 | 10 个越权测试全过 |
| **P1 单链** | 6–12 月 | M1（11 页）+ TES + 合规闸门 + 订单/TCA | 20 RM/100 客户/50 提案；周期 ≤ 4h |
| **P2 规模化** | 12–24 月 | M2 + M3（服务邀请）+ M4（估值/质押/信托）+ M5（5 家族） | 100% 压力覆盖；100% 内部复核 |
| **P3 复制** | 24–36 月 | 多品类服务、税务优化全量、开放 API | 48 页全量；零重大合规事件 |

**停止线**：规则误杀 > 20%、RM 修改率 > 60%、提案周期未降 30%、任一重大合规事件 → 暂停扩量，先修。

## 8. 还需要拍板的三件事

1. **M5 的"免费/收费"边界**：税务优化是 RM 服务的一部分（免费初诊），还是单独收费？建议：初诊/画像免费，深度方案由 HSBC 内部团队收费或打包。
2. **M5 的内部团队与外部律师**：HSBC 内部团队主导；是否需要建立外部律师面板（每法域至少 2 家）用于正式法律意见。
3. **M4 的信托消费**：是否统一采用"信托持有 + 使用协议 + 直付"三件套；是否接受 40% 追保作为标准条款。
